# Blackbook Event Reference

This document describes every event generated by Blackbook's event system.

## Event Storage Behavior

Blackbook events fall into two categories:

### Stored Events

Stored events are written to the agent event history (`agent.events`).

These events:

- Appear in the Timeline tab
- Appear in the Agent History view
- Are included in statistics calculations
- Are preserved through export/import
- Represent the permanent historical record of an agent

Most events are stored automatically because `storeEvent` defaults to `true`.

---

### Transient Events

Transient events are generated through the event system but are **not stored** in the agent event history.

These events:

- Do not appear in Timeline
- Do not affect statistics
- Do not increase event counts
- Are not exported
- May be useful for future synchronization, auditing, multiplayer, or cloud functionality

Transient events explicitly set:

```ts
storeEvent: false
```

# Sanity Events

| Action | Stored | Description |
|----------|----------|-------------|
| san-change | ✅ | SAN gain or SAN loss |
| breaking-point-reset | ✅ | Recalculated/reset Breaking Point |
| adaptation-incident | ✅ | Recorded adaptation progress |
| adaptation-applied | ✅ | Applied or removed an adaptation |

SAN events may additionally track:

- Actual SAN loss
- Projected bond damage
- Breaking Point crossings
- Temporary insanity
- Adaptation completion
- SAN type (Violence, Helplessness, Unnatural)

# Summary

## Stored Event Categories

- Attribute
- Bond
- Condition
- Disorder
- Equipment
- Home Scene
- Marker
- Motivation
- Sanity
- Skill
- System (aliases only)
- Wound

## Transient Event Categories

- Character
- Notes
- Photo updates
- Detail updates
- Personal data edits

These transient events currently exist primarily for future event-stream expansion and synchronization capabilities.
